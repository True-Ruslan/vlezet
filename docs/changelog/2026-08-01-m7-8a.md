# M7.8A — Recognition Benchmark Foundation

**Date:** 2026-08-02  
**PR:** #40  
**Status:** automated acceptance passed; product-owner review pending.

## Why

The assisted-recognition workflow already preserved the correct safety boundary—editable Draft plus explicit Apply—but recognition accuracy remained visually judged and fixture-specific. Tuning Canny, Hough, line merging or prompts without a stable corpus could improve one plan while silently degrading others.

M7.8A creates the measurement authority required before M7.8B–M7.8D change recognition quality.

## Delivered

### Corpus and contracts

- exactly eight versioned source fixtures covering clean, dense, degraded and perspective cases;
- synthetic or redrawn-anonymized provenance only;
- immutable source hashes and raster metadata checks;
- fail-closed fixture, result and baseline schemas;
- reference-local millimetre coordinate authority;
- no original private regression plan in the repository.

### Deterministic scoring

- maximum-cardinality/minimum-cost entity assignment;
- wall geometry and topology scoring;
- opening matching with host-wall correctness;
- room, room-area and total-area scoring;
- confidence and reconciliation integrity metrics;
- explicit `not-applicable` semantics;
- committed baseline and regression comparison;
- documented `0.000001` continuous-metric allowances and zero allowance for defect-count increases;
- explicit rejection of schema, corpus, fixture-set, engine-version and applicability migrations.

### Browser source benchmark

- existing local OpenCV pipeline extracted into one browser-compatible engine;
- production Worker retained as protocol adapter;
- algorithm constants and progress phases preserved;
- benchmark-only guarded Next.js route;
- real Chromium/OpenCV execution for all eight source images;
- production Worker/shared-engine semantic equality;
- source predictions, scored result and Markdown report;
- deterministic SVG overlays embedding each source plan with expected and predicted walls/openings plus colour-independent TP/FP/FN annotations.

### CI and evidence

- Core Benchmark integrated into Standard CI;
- dedicated Recognition Benchmark workflow;
- fixture privacy/integrity verification;
- no secrets and no live provider calls;
- one self-contained evidence directory containing Core result, Source result, aggregate summary, all eight overlays and portable `SHA256SUMS`;
- Chromium and WebKit product-regression coverage.

## Defects resolved during delivery

- Next.js treated `app/__recognition-benchmark` as a private folder, so the harness URL returned 404; the route now uses an encoded leading-underscore segment and remains environment-gated.
- The extracted recognition engine called a detached `crypto.randomUUID` reference, which could fail with `Illegal invocation`; the browser `Crypto` receiver is now preserved.
- Baseline comparison initially treated two `not-applicable` metrics as errors; equal applicability is now omitted while applicability drift fails closed.
- The first checksum manifest referenced files outside its directory; evidence now copies both scored results into one autonomous bundle verified by `sha256sum -c`.
- Initial files described as overlays were ordinary screenshots of the benchmark harness without plan geometry; they were removed and replaced by deterministic source-plan SVG overlays generated from the actual scorer matches.
- Baseline comparison originally used a generic floating-point epsilon and ignored engine-version drift; it now implements the documented metric-specific allowances and explicit migration checks.

## Architecture preserved

No changes were made to:

- `VlezetDocument`, domain schema, migrations, IndexedDB or portable project format;
- recognition Apply semantics;
- editor-core validation and history authority;
- M2 fit/collision authority;
- planning or 3D;
- OpenRouter production behaviour.

M7.8A does not claim quality completion. The recorded baseline is intentionally low and exposes the exact work required in M7.8B.
