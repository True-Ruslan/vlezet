## Why

M7.1 established a stable editor shell and M7.2 unified context surfaces, but essential typography, fields, notices, badges, cards and dialogs still used partially duplicated presentation rules. Later workflow redesigns required a governed component foundation before further product-specific UI work.

## Delivered

- semantic design tokens for typography, spacing, colors, radii, shadows, focus and control sizes;
- balanced density: 14 px ordinary text, 13 px compact panel text and 12 px meaningful minimum;
- store-free shared buttons, fields, messages, notices, badges, cards, empty states and dialogs;
- native disabled/busy semantics, focus management and non-color status cues;
- Russian presentation formatting for millimetres, square metres and degrees;
- representative migration of room controls, furniture catalogue, fit statuses, dashboard, project deletion, OpenRouter dialog and recognition UI;
- Canvas helper text raised to the governed minimum;
- expanded Chromium/WebKit evidence preserving M7.1/M7.2 behaviour.

## Manual-acceptance defects fixed

### Safe global keyboard handling

A runtime `keydown` event without a string `key` caused `event.key.toLowerCase()` to throw while opening planning. The handler now fails closed for malformed/unknown events while preserving `M`/`m` measurement activation.

### OpenRouter malformed structured output

OpenRouter requests now opt into response healing while retaining strict JSON Schema validation:

```json
"plugins": [{ "id": "response-healing" }]
```

### Stale recognition decisions

Repeated AI checks can replace cloud candidates. Reconciliation now retains decisions only for candidate IDs present in the final walls, openings and room-label collections; new candidates receive `pending`, removed references are discarded.

## Deferred recognition-quality limitation

Manual testing confirmed that the OpenRouter flow completes, but the reconstructed plan can still be structurally inaccurate. The observed result contained 16 wall candidates, 7 openings, only 3 confident candidates and 26 requiring review.

This was deliberately not hidden or folded into M7.3. Future ownership:

- `docs/product/RECOGNITION_QUALITY_REQUIREMENTS.md`;
- issue #27 — M7.8 recognition topology, openings, rooms and area accuracy.

The future milestone requires a benchmark corpus, deterministic topology post-processing, door/window host validation, room-face derivation, OCR/area constraints and measurable accuracy thresholds.
